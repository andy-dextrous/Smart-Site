# SmartSite Docs

This is the canonical docs harness for SmartSite as a standalone starter.

## Task routing

- Section or block work:
  [docs/engineering/section-development.md](engineering/section-development.md),
  [docs/engineering/design-system.md](engineering/design-system.md),
  [docs/engineering/coding-standards.md](engineering/coding-standards.md)
- Site configuration, features, AI, search, or collection customization:
  [docs/workflows/feature-toggles.md](workflows/feature-toggles.md),
  [docs/engineering/configuration-system.md](engineering/configuration-system.md)
- Admin boundary or questions about whether something belongs in `src/admin`:
  [docs/engineering/admin-layer.md](engineering/admin-layer.md),
  [docs/rules/agent-guardrails.md](rules/agent-guardrails.md)
- Deployment, preview, backup, restore, or recovery:
  [docs/product-specs/hosting-modes.md](product-specs/hosting-modes.md),
  [docs/workflows/deployment.md](workflows/deployment.md),
  [docs/workflows/preview-environments.md](workflows/preview-environments.md)
- Day-to-day development workflow:
  [docs/workflows/development.md](workflows/development.md)
- Startup or first install:
  [docs/workflows/getting-started.md](workflows/getting-started.md)
- Routing, slug, cache, or stale-page behavior:
  [docs/workflows/troubleshooting.md](workflows/troubleshooting.md),
  [docs/engineering/routing-and-caching.md](engineering/routing-and-caching.md)
- Big-picture product framing only when the task needs it:
  [docs/PRODUCT.md](PRODUCT.md)
- Harness rules only when the routing itself is unclear:
  [docs/DOCS.md](DOCS.md)
- ExecPlan rules only when the task is specifically about writing or editing an ExecPlan for a substantial slice, not for routine section work or small UI tweaks:
  [docs/PLANS.md](PLANS.md)

Do not use `README.md`, `docs/references/`, or legacy docs as the first retrieval path for active SmartSite work.

## Canonical homes

- [docs/PRODUCT.md](PRODUCT.md): what SmartSite is and the supported operating shapes.
- [docs/workflows/index.md](workflows/index.md): exact setup, development, deployment, and preview procedures.
- [docs/engineering/index.md](engineering/index.md): architecture, design-system, section-building, routing, and configuration truth.
- [docs/rules/index.md](rules/index.md): hard constraints for agents and implementers.
- [docs/references/index.md](references/index.md): the README manuscript and any future legacy references.
