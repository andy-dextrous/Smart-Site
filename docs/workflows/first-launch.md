# First launch and deliberate content transfer

The agent prepares the actual local site, a browser preview and a destination report. Record the domain, hosting account, destination site ID, database, durable storage, email behavior, approved content/publication scope and rollback. Ask only for missing business/access/publication decisions. Hosting writes and purchases need the actual request to cover them.

Provision the destination independently with a new UUID, secret, database and storage. Set `SMARTSITE_SITE_ID`, `SMARTSITE_ENVIRONMENT`, `DATABASE_PROVIDER`, `DATABASE_URL` and public URL explicitly. An authorized CMS operator creates its identity using the reviewed environment-adoption helper; local bootstrap must never adopt a hosted database. Create a destination administrator through normal CMS first-user setup and scope MCP keys to that operator. Do not copy local users/keys/secrets.

Use `node scripts/content-transfer/run.mjs --request <private-json>` for selected content. This is an internal deterministic helper invoked by the launch skill. Request files and bundles contain content and remain private under `.smartsite/transfers/`.

An export request has `schemaVersion: 1`, `action: "export"`, `environmentFile`, `expectedSiteId`, `operatorId`, `bundleFile`, `reportFile`, and `selection: [{target:"pages",id:"..."},{target:"header"}]`. The helper follows approved content relationships and reports excluded references. For remote media, explicitly download the approved assets and provide `mediaFiles: {"source-media-id":"/absolute/private/file"}`; it never fetches arbitrary URLs. This bounded transfer supports PNG/JPEG/WebP up to 2 MiB; use a reviewed storage migration for larger/other assets.

An import request uses `action:"import"`, the destination environment/identity/operator, `bundleFile`, the export report's `bundleChecksum`, and `receiptFile`. Default is dry run. Provide `referenceMappings: [{target:"users",sourceId:"...",destinationId:"..."}]` for excluded relationships. Optional omitted fields must be explicitly listed in `optionalOmissions` using the reported `target.fieldPath`; required references block. Mapping verification runs again on apply, so deleted accounts cannot silently become dangling links. It never creates accounts by matching emails/names.

Review dry-run order, publication modes, omissions, schemas, global before/after values and destination emptiness. The private import-plan.json binds this review to the bundle, destination, operator and mappings. Apply rejects globals changed since that review; rerun dry run and review rather than forcing a new revision. Cycles or already populated destination content require a separately reviewed migration, not a forced overwrite. Apply only under publication authorization with `apply:true, approvedPublication:true`. Preserve the receipt and exact bundle. Once any operation has started, its operator, reference mappings and omissions are fixed; changing them requires a separately reviewed reconciliation, not a fresh dry run that reuses the old receipt. Retry with that receipt; never generate a new one to work around a conflict. Existing imported records are checked before resuming. Global before-states are recorded for selective rollback. This is a deliberate first-import tool, not general synchronization.

Verify the resulting relationships, media URLs, navigation, forms, metadata, draft/public behavior and pages in the real destination app. URL strings that encode a source hostname require explicit review; relationship remapping does not rewrite arbitrary prose or links. Transfer includes selected current content/publication intent, not old history or private account data. Later code deployments do not rerun transfer.
